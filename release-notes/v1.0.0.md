# pkinative-mcp v1.0.0 — First stable release

<!-- GitHub Release title: v1.0.0 - First stable release: 34 PKI tools on pkinative 1.0.0, OpenSSL-validated, no network, no key byte leaving -->

_Released 2026-10-13_

**Built on:** [pkinative v1.0.0](https://github.com/Nizoka/pkinative/releases/tag/v1.0.0)

The first stable release — and the first npm publication — of the Model Context
Protocol server for pkinative, the zero-dependency, pure-TypeScript PKI engine
(Web Crypto for every signature). 34 tools expose the engine's frozen 1.0 surface
to any MCP client: inspect and verify X.509 certificates, CSRs, CRLs, OCSP responses,
CMS SignedData and RFC 3161 time-stamps; build and validate certification paths
(RFC 5280 §6, server name, purposes, policies, offline CRL / OCSP revocation); create
certificates, CSRs, CMS signatures, OCSP and time-stamp requests through
non-extractable Web Crypto keys; open PKCS#8 and PKCS#12 without ever returning a key
byte; decode and encode ASN.1, PEM and OIDs; an offline capability manifest, a code
explainer and human-in-the-loop issue drafting. The tool API is
`_meta.apiVersion = '1.0.0'` and stable under `docs/API_STABILITY.md`; the bytes the
deterministic artefact tools emit are part of that contract. Three runtime
dependencies, no network code path, and every artefact the server writes validated by
OpenSSL 3 in a blocking conformance gate.

## Highlights

- **Full engine coverage, honestly graded** — every one of the 117 runtime exports of pkinative 1.0.0 is reached by a named tool (`tests/coverage-matrix.test.ts`, 117 / 117); the 177 type-only exports travel through the inputs and reports; the five surfaces deliberately left unexposed carry a rationale in `describe_engine.unexposed` and in `docs/KNOWLEDGE_BASE.md`. The 57 `PKI_*` error codes reach the client verbatim in `_meta.error.code` with `data.errorClass`, `engineError`, `path` / `offset` / `limit` and a remedy phrased as MCP inputs; the 43 `PKI_REASON_*` verdict reasons come back in `reasons[]` (never thrown); the 97 `PKI_DIAG_*` diagnostics travel on every result, de-duplicated and counted.
- **Verify before you trust** — `inspect_certificate` is facts, `verify_certificate_chain` is the verdict (path, signatures, validity at a pinned `at`, name, purposes, policies, offline revocation); `build_certificate_path` never checks signatures and says so on every result; a negative verdict is `valid: false` with `reasons[]`, never `isError`.
- **No network, ever** — no CRL / OCSP / AIA / TSA fetch, no telemetry, no URL from any argument: `create_ocsp_request` and `create_timestamp_request` produce the bytes the caller transports; `check_crl_revocation`, `check_ocsp_status`, `verify_cms` and `verify_timestamp` judge the evidence the caller brings.
- **No key byte leaves** — signing keys are imported as non-extractable Web Crypto handles; every key / PKCS#12 report is an allow-list view; `convert_pem`, `decode_asn1`, `encode_asn1` and `resources/read` refuse private-key material; the sandbox never writes nor serves a key-bearing extension (`.key`, `.p8`, `.p12`, `.pfx`); every test result that touches a key is swept with the needle table of the fixtures, and so is every document (`verify:docs` rule `no-secret-material`).
- **Doctrine surfaced, not hidden** — no key generation, no key export, no writer for PKCS#8 / PKCS#12 / CRL / OCSP responses / time-stamp responses, SHA-1 only with `allowSha1`, RSA only with an explicit `rsaScheme`, PBES2 / PBMAC1 only (a legacy PKCS#12 is refused with the OpenSSL 3.4 conversion as the remedy), DSA / ML-DSA parsed and never verified; `describe_engine.refusals` lists all of it at runtime.
- **OpenSSL as the external judge** — a 28-entry corpus (23 conformant artefacts, 5 refused canaries) written by the built server under a pinned instant and re-read by OpenSSL 3.x across 12 command families (`npm run corpus:pki && npm run validate:pki`), plus the read direction (OpenSSL wrote the 42 fixtures, the tools read and verify them) in `tests/interop/openssl.test.ts`; blocking on Linux and Windows, `PKINATIVE_INTEROP_REQUIRED=1` fails closed.
- **MCP 2026-07-28 and the hosts of today** — stateless serving, `server/discover`, the `_meta` envelope, `resultType`, cache hints (`tools/list` and `prompts/list` public 24 h, `server/discover` public 1 h, `resources/*` private); the automatic legacy `initialize` fallback for 2024-10-07, 2024-11-05, 2025-03-26, 2025-06-18 and 2025-11-25 on stdio and HTTP. Token-frugal `verbosity: 'summary'` / `fields` projections, produced bytes delivered once as an embedded resource, `pkinative://output/{+path}` resources, 7 prompts.
- **Docs as code** — `docs/assets/ecosystem.json` is the single source of every count and version; `npm run verify:docs` holds 27 rules over every document, agent file, example, release note and draft; `tests/docs-consistency.test.ts` holds them from the inside.

## Security

- **No network, ever** — there is no network code path in the server: `describe_engine.network` is `'none'`; every tool advertises `openWorldHint: false`; `draft_governance_issue` produces a local draft and stops.
- **feat(security):** one filesystem boundary (`PKINATIVE_MCP_OUTPUT_DIR`) for `path` inputs, `resources/read` and file-mode writes — relative paths only, NUL / absolute / drive / UNC / `..` refused, extension allow-lists for inputs and outputs (key-bearing extensions never written nor served), realpath re-check of every file read and of the parent of every write (a planted symlink or junction is `SECURITY_VIOLATION`), `wx` opens, partial files removed, never overwritten (`OUTPUT_EXISTS`); unset = no file I/O beyond the opt-in response cache.
- **feat(security):** operator ceilings `PKINATIVE_MCP_MAX_INPUT_BYTES`, `PKINATIVE_MCP_MAX_KDF_ITERATIONS` and `PKINATIVE_MCP_MAX_PATHS_EXPLORED` bound every per-call `limits` value (`LIMIT_CEILING_EXCEEDED` names the variable; an invalid value refuses to start); a byte envelope on every exchange (256 MiB frame, 128 MiB inline input per call, 1 GiB content via path, 50 MiB inline output, 1 GiB file output, 64 KiB hex, 200 diagnostics, 16 field paths).
- **feat(security):** two password channels that never meet — the per-call `password` input or `PKINATIVE_MCP_PASSWORD` in the server environment, never both (`VALIDATION_ERROR`); passwords are never echoed, logged or cached; only the presence of a secret is logged; a password-accepting call is never cached while the variable is set.
- **feat(security):** `sign_cms` parses every CRL before embedding it; `create_certificate` and `create_csr` verify the issuer signature and the proof of possession before the bytes return (`KEY_MISMATCH` otherwise); `amend_cms add-timestamp` checks the time-stamp imprint against the signature value before anything is written.
- **feat(security):** loopback-only Streamable HTTP (`PKINATIVE_MCP_PORT`) with a constant-time bearer token (`PKINATIVE_MCP_HTTP_TOKEN`, ≥ 16 characters), Host / Origin guard, 405 / 413 where due; stdio frames capped at 256 MiB.
- **docs(security):** `SECURITY.md` states the supported-versions policy, the threat model (the model and every input byte untrusted, the host and the operator trusted, one sandbox), what is and is not defended, "Network egress: none", release integrity and the compatibility promise.

## Added

### Encodings

- **feat(tool): `convert_pem`** — PEM ↔ DER, the labels of a bundle, one block by `extractIndex`; private-key material refused on extraction.
- **feat(tool): `resolve_oid`** — name / validate / list / encode / decode OIDs, up to 1000 per call, the registry filtered and paged.
- **feat(tool): `compute_fingerprint`** — SHA-1 (a digest needs no opt-in; only SHA-1 signatures need `allowSha1`) / SHA-256 / SHA-384 / SHA-512 and SHAKE fingerprints of a certificate, a public key or any DER, with `separator` and `letterCase`.
- **feat(tool): `decode_asn1`** — the DER / BER tree with offsets, a `nodePath` cursor, typed `read` of one node (boolean, integer, OID, string, time, …), `sequence: true` for concatenated objects; private-key material refused.
- **feat(tool): `encode_asn1`** — DER from a typed JSON spec (every universal type, tagging, named bits), delivered as PEM, DER or hex.

### Certificates and requests

- **feat(tool): `inspect_certificate`** — the RFC 5280 report of one certificate (19 extension kinds decoded, `rawExtensions`, one `extension` by kind, fingerprints), one optional signature check against `issuer` or `checkSelfSignature` — facts, not trust.
- **feat(tool): `create_certificate`** — a self-signed CA or an issued leaf from a spec, the subject public key from a certificate / CSR / PUBLIC KEY, `serialNumber: 'random'` reported as `randomSerial`, the issuer signature verified before the bytes return.
- **feat(tool): `encode_x509_structure`** — the DER of a Name, an Extension, an AlgorithmIdentifier, a Validity or a TBS structure from the same spec vocabulary.
- **feat(tool): `decode_extension`** — one extnValue content decoded by `oid` exactly as `inspect_certificate` would, `critical` checked against the RFC 5280 rule.
- **feat(tool): `check_certificate_name`** — RFC 6125 host / address matching against the SAN (`allowWildcards`, `allowCommonNameFallback`), or `presented` / `reference` directly.
- **feat(tool): `check_certificate_purpose`** — extended key usage and key usage against a purpose, through a chain with `restrictIssuers`.
- **feat(tool): `inspect_csr`** — the PKCS#10 report with the requested extensions, `verify: true` for the proof of possession.
- **feat(tool): `create_csr`** — a PKCS#10 request from a spec and a signer, the proof of possession verified before the bytes return.

### Paths, CRLs and OCSP

- **feat(tool): `verify_certificate_chain`** — the RFC 5280 §6 verdict at a pinned `at`: path discovery, signatures, validity, `serverName`, `purposes`, `policy`, offline revocation from `crls` / `ocspResponses` (`requireRevocation`, `ocspNonce` / `requireOcspNonce`).
- **feat(tool): `build_certificate_path`** — path discovery only (bounded by `maxPathsExplored`), signatures never checked and `PKI_REASON_SIGNATURE_NOT_CHECKED` always present.
- **feat(tool): `validate_certificate_path`** — a path the caller ordered, signatures checked, policies processed.
- **feat(tool): `inspect_crl`** — the CRL report, one entry by `find`, an optional issuer signature check.
- **feat(tool): `check_crl_revocation`** — one certificate against a CRL (and a `delta`), with `staleTolerance` and the issuer signature.
- **feat(tool): `create_ocsp_request`** — the OCSP request bytes (SHA-1 CertID by default, as RFC 6960 says; `hashAlgorithm` for SHA-256), `nonce: 'random'` reported as `randomNonce`, `certIdOnly` for the bare CertID.
- **feat(tool): `inspect_ocsp_response`** — the response report with the responder certificate chain, an optional `responder` signature check.
- **feat(tool): `check_ocsp_status`** — one certificate's status from a response the caller fetched: responder trust, nonce, `staleTolerance` / `futureTolerance`, at a pinned `at`.

### CMS and time-stamps

- **feat(tool): `sign_cms`** — CMS SignedData, attached or detached, `contentDigest` for pre-hashed content, `sid`, `signingTime`, signingCertificateV2, algorithm protection, signed / unsigned attributes, embedded `chain` and parsed `crls`.
- **feat(tool): `verify_cms`** — the one verdict: signatures, chains to `trustAnchors`, embedded time-stamps (`atTimeStamp`), offline revocation, `requireSigningCertificate`, `requireAlgorithmProtection`.
- **feat(tool): `inspect_cms`** — the SignedData facts (`signerSignature` is a key check, not trust), one signer by `signerIndex`, the detached `content` for the digest.
- **feat(tool): `amend_cms`** — add or remove an unsigned attribute, or counter-stamp a signer with `add-timestamp` (the imprint checked against the signature value).
- **feat(tool): `create_timestamp_request`** — the RFC 3161 request from `data` or `digestHex`, `nonce: 'random'`, `policy`, `certReq`.
- **feat(tool): `inspect_timestamp`** — a response, a token or a bare TSTInfo (`as`), the TSA chain and the imprint.
- **feat(tool): `verify_timestamp`** — the token or the response against the request / the data, the TSA chain to `trustAnchors` (`allowNonCriticalTimeStampingEku`), offline revocation, at a pinned `at`.

### Keys

- **feat(tool): `inspect_private_key`** — a PKCS#8 key described without a password (algorithm, curve, encryption scheme, KDF parameters); `tryImport` with the password proves it imports — no key byte in any report.
- **feat(tool): `inspect_pkcs12`** — the PKCS#12 structure described without a password (bags, ciphers, MAC scheme, the certificates).
- **feat(tool): `open_pkcs12`** — the file opened with the password: key handles described, certificates optionally exported, `allowUnverifiedIntegrity` only for a file whose origin is trusted; `RSA_SCHEME_REQUIRED` for an RSA key without `rsaScheme`.

### Meta

- **feat(tool): `describe_engine`** — the offline capability manifest: versions, Web Crypto capabilities, the 22 named limits and their ceilings, caps, sandbox state, the code vocabularies, refusals, unexposed exports.
- **feat(tool): `explain_code`** — any wrapper code, `PKI_*` error, `PKI_REASON_*` reason or `PKI_DIAG_*` diagnostic explained with its remedy, or the whole list by `kind`.
- **feat(tool): `draft_governance_issue`** — a local, compliant issue draft plus the compliance report; `GOVERNANCE_VIOLATION` on a contract breach; never submitted.

### Server and protocol

- **feat(mcp):** MCP 2026-07-28 on `@modelcontextprotocol/server` ^2.0.0 with legacy fallback for the five 2024 / 2025 revisions on stdio and HTTP; cache hints; `_meta.apiVersion` / `_meta.examples` (at most two per tool, each executable) / `_meta.error` (with `data.remedy` whenever a remedy applies) / `_meta.cached` / `_meta.unmatchedFields`; resources `pkinative://output/{+path}`; 7 prompts (`governance_contract`, `draft_issue_workflow`, `verify_before_trust`, `issue_certificate`, `sign_and_timestamp`, `offline_revocation`, `open_keys_safely`); `-32602` for an unknown tool, prompt or resource.
- **feat(transport):** stdio (256 MiB frame) and loopback Streamable HTTP (`PKINATIVE_MCP_PORT`, `PKINATIVE_MCP_HTTP_TOKEN`).
- **feat(time):** `PKINATIVE_MCP_AT` pins the instant of every omitted `at` / `notBefore` / `signingTime`; an unpinned instant is never cached.
- **feat(cache):** opt-in content-addressed response cache (`PKINATIVE_MCP_CACHE_DIR`, 1 h TTL, 256 MiB) with an engine-namespaced key and a strict never-cache list (a `path` input, a password, a signer, file mode, `'random'`, `'now'`, an unpinned instant, `describe_engine`, `draft_governance_issue`).
- **feat(errors):** 21 wrapper codes, each with a remedy (`src/wrapper-codes.ts`), plus the engine vocabularies verbatim; `strict: true` escalates the first warning diagnostic to `PKI_STRICT_DIAGNOSTIC`.
- **feat(governance):** `.github/ai-governance.json`, `.github/AGENT_RULES.md` (rule 8: human-in-the-loop), `scripts/verify-issue.mjs`, the `governance_contract` / `draft_issue_workflow` prompts, the Claude Code guard hook on Bash and PowerShell.

## Inherited from pkinative 1.0.0

- The frozen 1.0 vocabularies: 57 error codes, 43 verdict reasons, 97 diagnostics and the 22 named `PkiLimits`, vendored from the engine's release tag under `src/data/pkinative/` (gate step `code-tables` regenerates the TypeScript tables; `tsc` fails here the day the engine adds a code).
- The engine's architecture decisions, surfaced as doctrine: no key generation (ADR 0001), no writer for PKCS#8 / PKCS#12 / CRL / OCSP responses / time-stamp responses (ADR 0003), no default RSA signature scheme (ADR 0015).
- The engine's remedies, rephrased as MCP inputs in `data.remedy` (`src/pki-errors.ts`); the OpenSSL 3.4 conversion for a legacy PKCS#12 and the PBES2 re-encryption for a legacy PKCS#8 key quoted verbatim.
- Engine issues closed before 1.0.0 are listed in the engine's own release note (see Links); none was reopened by this server.

## Deferred by design

- **Nothing fetches** — CRL, OCSP, AIA and TSA retrieval stay on the caller's side by doctrine; the server never will.
- **No key generation, no key export, no key-bearing writer** — bring keys from an HSM, a KMS or `openssl genpkey`; produce PKCS#12 / CRL / OCSP responses / time-stamp responses with the issuing software and verify them here.
- **DSA, ML-DSA and unknown key kinds** are parsed, never verified or signed (`PKI_REASON_SIGNATURE_NOT_CHECKED` / `UNSUPPORTED_KEY`); EC P-256 / P-384 / P-521, RSA, Ed25519 and (where the host supports it) Ed448 sign and verify.
- **SHA-1 and legacy ciphers** stay opt-in or refused: `allowSha1: true` per call, PBES2 / PBMAC1 only.
- **No superset gate before 1.1.0** — `tests/_fixtures/tool-shape.v1.0.0.json` freezes this catalogue; the compatibility comparison against it starts with the first release that has something to compare (the parity gate against `tool-shape.json` is active now).
- **Two of the 97 diagnostics reach the client from the fixtures** (`PKI_DIAG_COMMON_NAME_NOT_IN_SAN`, `PKI_DIAG_CMS_SET_NOT_SORTED`); 30 more are proven with hand-built values through `decode_asn1` / `decode_extension`; the remaining 65 need a crafted certificate, CRL, CMS, OCSP or PKCS#8 object the suite does not build — each is listed with that reason in `tests/diagnostics-inventory.test.ts`.
- Everything else planned is in `ROADMAP.md`.

## Upgrade

First release — nothing to upgrade from. The tool API starts at `1.0.0`; from here on, `docs/API_STABILITY.md` governs every change (the bytes of a deterministic artefact are byte-identical across patch and minor releases; a change to them is major).
